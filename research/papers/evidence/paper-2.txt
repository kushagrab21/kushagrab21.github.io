      Where a Coding Agent Decides It Is Finished?

                                 Kushagra Bhatnagar

                                      August 2026


                                       Abstract
A coding agent given a channel to declare its own work finished will sometimes use
it on work that is not finished. The previous paper in this programme showed that
moving the authority to end a task from the model to a checker changes outcomes,
and that the size of the change tracks how often the model wrongly claims completion.
What that design could not show is where the wrong claim happens or why, because
a claim could arrive at any turn and the corpus was built to measure something else.
This paper builds the instrument that isolates it. Each task is a short broken Python
function whose correct behaviour depends on a convention the task never states. The
tests that enforce the convention arrive one stage at a time as the visible ones pass, and
the model may end the episode at any point by replying with the single word DONE,
which the harness scores against every test the model has not seen and never reports
back. The instrument therefore controls exactly what the model knows at every turn,
and it locates the failure at a single state: the moment every visible test passes while a
stage is still hidden. Across eleven runs of three models and 856 episodes at $55.21 of
booked compute, 73 of the programme’s 74 wrong claims were made at that state, and
none after a submission that left a visible test failing. Three explanations for the failure
are then eliminated in turn. The model is not missing information, because telling it
exactly how many stages are hidden left claiming unchanged at 6 tasks moving each
way of 115. It is not following an incentive, because telling it that stopping early is
rewarded did not raise claiming. And it is not blind to the risk, because it claims at 97
of 117 visits where claiming is safe but only 23 of 121 where it is not. What does move
the behaviour is doing the arithmetic for the model: printing the count of hidden
stages into the feedback at the moment of the decision moved 13 tasks against 1 and
halved the wrong claims. The control that would show whether the content of that
line or merely its presence did the work has not been run.


1 Question
The previous experiment in this programme ended with a practical rule and an
unanswered question. The rule was that completion gating pays inside a window of
capability: a model strong enough never to claim wrongly gains nothing from the


                                             1
gate, a model too weak to repair on feedback is hurt by it, and the models in between
are rescued in proportion to how often they claim wrongly in the first place. The
unanswered question was what the wrong claim is. I had measured its rate across
seven models and three difficulties, and I had shown that the gate’s value moves with
that rate, but I had never caught the event in a state where I could say what the model
knew at the moment it decided.
The gap has a practical consequence. If a wrong claim is a slip then a checker is the
fix, but if it is a reasoning failure about unseen evidence then a checker only masks it,
and every agent that runs without one keeps making it. Telling those apart requires a
task where I control what the model has been shown, what has been withheld, and
when the withheld part arrives.
The design: Each task is a short broken Python function with a test suite. The function
is pure, under forty lines and free of docstrings or comments, so repairing it looks
mechanical, and the difficulty sits somewhere else: the code has to make a decision
that nothing the model can see states, and a hidden suite enforces one particular
answer to it. Is a record with no value field an error, a null, or a zero? Does a range
include its upper bound? When every score in a group is null, is the average None or
zero? Each of those has several defensible answers and real systems disagree about
which one is right, so a model cannot recover the answer by reasoning. It can only
guess, and the corpus is built so that guessing loses.
What stays measurable is whether the model notices that it is guessing, and that is
what the staged release is for. The tests that enforce the withheld convention do not all
arrive at once: a task ships with the tests the model can read plus a chain of withheld
stages, and one more stage is released only when everything currently visible passes.
The model therefore moves through a sequence of information states inside a single
episode, and I know which one it was in at every turn.
Onto that loop the experiment adds one binary channel: the model may reply with the
single word DONE instead of code, which asserts that the work is finished including
the parts it has not been shown. The harness scores that assertion against the full suite,
ends the episode, and tells the model nothing, so a claim is a bet placed on evidence
the model does not have. The record of the bet is complete, because I know the board
it was looking at, how many stages were still hidden, and whether it was right.
Relevance outside the laboratory: No specification is ever complete. Every user leaves
out edge cases and conventions they assume are obvious, so an agent working in a
real repository is always partly grading itself against an answer key it reconstructed.
Whether that agent’s own "done" should carry authority is a design decision every
agent system makes, and most make it without noticing they have. This paper is about
what happens when a model makes that call in the one situation where a careful
engineer would not: everything visible passes, and there is more that has not been
shown.

2 The previous result and its limits
Established results: The previous experiment compared two agent designs on a repair
corpus: in the first the model could declare the task finished and the declaration was
believed, while in the second the declaration was ignored and the episode ended only
when the checker passed. Everything else was held identical, down to byte-identical
feedback text, so the only varying factor was who held the authority to end the episode.
That paper named this failure the false-DONE, and this paper calls the same event a
wrong claim and uses that name throughout.
Three results carried forward into this one. The gate helps by converting wrong claims
into forced repairs, so its value is the rate of wrong claiming times the model’s ability
to repair once refused, and that value is zero at both ends of the capability range for
opposite reasons: a model at the ceiling never claims wrongly and has nothing to
convert, while a model below the floor cannot complete the repair it is forced into.
And the window is a property of the model rather than of the model and task together,
because raising task difficulty deepened the window for models already inside it and
never dragged a stronger model in.
The three limits: That design had three limits, and this paper addresses them.
The wrong claim had no located moment, because a model could declare completion at
any turn, from any state, and the design recorded that it happened without recording
what the model was looking at when it happened. That leaves a rate and no state, and
since a rate can be lowered by many different mechanisms, a rate on its own does not
say which mechanism to intervene on.
The corpus could not separate a model that did not know from one that did not check,
because its tasks were bugs with a determinate correct fix, hidden only by stripping
the description: a model that failed had either missed something present in the code
or guessed wrong about something absent from it, and nothing in the record said
which. The corpus here is built the other way round, since the answer is absent from
what the model is handed by construction, and the question is only whether the
model notices.
And the models were never asked to reason about what they had not seen, since
nothing in that harness told a model that anything was withheld. A claim made on a
green board was therefore not obviously irrational, and the available explanation for
the whole effect was that the model did not know there was more. That explanation is
the first thing this paper tests, and Section 6 removes it.


3 The instrument
The corpus: The tasks are generated rather than collected, because the property this
paper needs is one no real repository can guarantee: that the correct answer is not
derivable from what the model was handed. Each task is a short pure Python function
with a defect, and behind the defect sits a hidden convention, which is a decision


                                           3
the code must make that the description never states and that several competent
developers would answer differently.
Three admission rules keep the corpus measuring withheld information rather than
trivia: every convention family lists at least three plausible readings, so a guess cannot
be a coin flip; every family and every individual reading carries attestations from at
least two unrelated domains, so each convention is one that real systems disagree
about rather than one the author invented; and where the withheld decision can be a
value drawn from a large space, that is preferred over a choice between enumerated
branches, because the size of the space then bounds how much a model could recover
by guessing. The catalogue behind the corpus records 93 attested readings with
186 attestations across 41 domains, running from numbered standards to product
behaviour to regulatory practice. The first corpus holds 452 tasks and the second,
built afterwards to pin mechanical difficulty flat so that the only remaining variation
is what the task withholds, holds 159, of which 119 are the working set the later
experiments play.
Staged release: A task ships the tests the model can read plus a chain of withheld
stages, and a stage is released only when every test currently visible passes. The depth
of the chain is certified so that no stage can be skipped, because at no point does the
information for stage k exist inside the stages before it. The consequence is the one the
experiment needs: passing everything visible is the trigger that reveals more work, so
it is the last thing a model should read as evidence that the work is over.
The loop and the claim: Figure 1 draws the harness: the model submits code, a
checker runs the tests it is allowed to run and reports which failed, and the loop
repeats. Two things are added to that ordinary loop: the tests arrive in stages, as
above, and the model may reply with the single word DONE instead of code, which
ends the episode. The harness then runs the entire suite including every unreleased
stage, records whether the claim was true, and reports nothing back. A reply counts
as a claim only when the whole reply is the token, so a message that merely mentions
the word is treated as a submission.
The vocabulary: A task is one broken function and its suite. A stage is a batch of tests
the model cannot yet see, and a release is the harness showing it one more stage. An
episode is one model working one task from the first message to the end, a turn is one
message from the model inside an episode, a submission is a turn carrying code, and a
claim is a turn carrying the token. An arm is one set of rules, differing from another
arm in exactly one sentence. A run is one model playing every task in a list once under
one arm, and an experiment is one comparison between arms, with its predictions
written down and frozen before the first episode.

4 The decision point
The state: Figure 2 draws the moment this paper is about, and it can be built from
nothing in three steps. The model has just submitted code, and every test it is allowed
to see has passed. That pass made the harness release a fresh stage of tests, which is
itself information, because it says the task held more than the model had so far been
shown. And at least one further stage is still withheld, though this last fact belongs to
the harness rather than to the model, since nothing the model can see says whether
the stage it was just handed was the final one. The model therefore holds its own
code, the tests it has passed, its transcript, and the rules’ statement that tests it has
not been shown exist, while it lacks the content of any hidden stage, the knowledge
of whether one remains at all, and any way to run what it cannot see. A board on
which nothing is failing is therefore compatible with two different worlds, a task that
is finished and a task that is not, and the two are indistinguishable from the model’s
seat. That indistinguishability is the whole state, and it is the decision point.
The two moves and their prices: Exactly two moves are available from that state, and
the harness prices them differently. Saying DONE ends the episode on the spot: the
harness grades the code against the full suite including everything withheld, records
whether the claim was true, and tells the model nothing, so a right claim ends a
finished task a few turns early while a wrong one ends an unfinished task for good.
Submitting again costs nothing: the visible tests re-run, the next stage is released
when they pass, and the model returns to the same kind of state holding strictly more
information than before. The trade is therefore one-sided by construction. A claim can
win at most a slightly earlier finish, it risks the task itself, and the move that removes
the risk is free, so the rational policy on this harness is plain: keep submitting until
nothing is withheld, and claim then. A claim at the decision point is never forced by a
budget, and is always a choice to stop early on evidence the model does not have.
The location of the wrong claims: Table 2 sorts every DONE in the programme by what
the model could see when it said it, and the sort shows the models holding to the
rational policy almost everywhere. Claims made once every stage had been released,
when nothing was hidden and the model had watched the whole suite pass, were
made 344 times and were never wrong. The departures are the claims made at the
decision point, and they carry nearly the whole cost, because of the programme’s 74
wrong claims, 73 were made there. Figure 3 draws the same split, for the programme
and run by run. One further claim completes the count: it was made before any test
had run, by the middle model in Experiment 1, which replied DONE on its first turn
having made zero submissions, and it was wrong.
Claims from a failing board: The harness allows a model to reply DONE from any
state, and that includes the state where a test it can see is failing. Across the eleven
live runs there were 115 turns in which the previous submission had left a visible test
failing, and the number of claims made from those turns is zero. That zero rules out a
simpler reading of the result, because a model claiming to escape a hard task would
claim from a red board and none ever did. No claim in the programme was made
after a submission that left a visible test failing.

5 Experiment 1: capability and wrong claims
Bridge from the decision point: Section 4 located the failure without saying whose
failure it is. A state where wrong claims concentrate could be a property of one weak
model, in which case the finding is about that model, or a property of the channel, in
which case it is about any agent given one. Experiment 1 separates those by holding
the tasks and the rules fixed and varying only the model, because if wrong claims are
a weakness, the strongest model should make the fewest.
Preconditions: Experiment 1 ran three models of different strength over the same
68 tasks in the same frozen order, under the two arms Section 3 defined: BIND, the
plain rules with no way to declare the work finished, so an episode ends only when
the suite is passed or the submissions run out, and ADV, the same rules plus the
paragraph that opens the DONE channel. The tasks span the corpus’s difficulty bands,
and the two ends of that range matter for what follows: in the easy band every test that
enforces the hidden convention is visible from the first turn, so nothing is withheld
and a green board means what it says, while in the hardest band the enforcing tests
are withheld and released in stages, so the decision point of Section 4 occurs there.
The models are ranked by the programme’s own capability labels, fixed before the
run and not derived from these results, and the three rungs of Table 3, strongest to
weakest, print that ranking. Everything except the model and the arm is held fixed, so
the scale follows from the design: 3 models × 2 arms × 68 tasks, which returned 407
completed episodes once one transport failure is excluded, at $16.74.
Predictions: The predictions compare the two arms task by task, and they lean on
one measure that needs defining first: a task is rescued when the same model failed it
under ADV and solved it under BIND, so the rescue count is the number of tasks on
which removing the channel turned a failure into a solve, and the benefit of removing

Inference: P1 is confirmed. The confirmation is evidence about existence and not about
a rate, because a count of 4 cannot support a magnitude, and the registration said so
in advance. No claim about how often this happens is made here and none should be
made downstream of these counts.
Scoring the predictions: Three of the four did not confirm. P2 is recorded as neither
confirmed nor disconfirmed, because its two registered clauses did not cover the
whole range of outcomes and the run landed in the gap between them: the predicted
ordering held, but the middle model’s test rested on a single task that changed answer.
P3 is disconfirmed in the opposite direction to the one predicted, since the rescue rate
in the hardest band was 7 of 96 against 1 of 107 in the easy band, roughly eight times
higher rather than lower, and Table 3B prints the two bands. P4 is disconfirmed on
its ordering clause, because the model with the largest benefit and the model with
the most wrong claims are different models. Reporting these as failures rather than
adjusting them afterwards is what the registration was for.
The interpretation of P3’s reversal: The prediction assumed that a gate cannot supply
withheld information, which is true, and concluded that the gate would therefore
help less where information is withheld, which turned out to be false. The mechanism
is visible in P1: in the hardest band the model under ADV ends episodes early by
claiming, while BIND has no way to end early except by actually passing, so the gate is
not supplying the missing bits but denying the model the option of declaring victory
without them.
Cost: $16.74 across 407 episodes.

6 Experiment 2: the information explanation
Bridge from Experiment 1: Experiment 1 left one explanation standing, and it is the
obvious one: the model claims because it does not know how much is still hidden. The
rules that open the claim channel tell the model only that tests it has not been shown
exist, and that is the whole of what it is told. They never say that those tests arrive in
stages, never give their number, and never distinguish a task that hides something
from one that does not, so a model reasoning correctly from what it was told could
treat a green board as the best evidence it will ever be given and stop there. If that is
the mechanism, then handing the model the missing number should reduce claiming,
and the fix for the whole failure would be one sentence of prompt. Experiment 2 tests
exactly that.
Changes from Experiment 1: Three things, each for a reason. The corpus is new:
these are the second corpus’s 119 working tasks from Section 3, built with mechanical
difficulty pinned flat, so the tasks differ in what they withhold and not in how hard
the repair is. The models are reduced to one, the strongest from Experiment 1, because
it claimed the most and was wrong the most, so it gives the comparison the most
events to read. And the shape of the comparison changes: Experiment 1 compared
having the claim channel against not having it, while this and every later experiment
compares two versions of having it, identical except for one sentence, so that whatever
differs between the arms can be attributed to that sentence alone.
The two arms: CTRL is the control arm, and it is Experiment 1’s ADV contract
imported and asserted byte-identical, so it says nothing about staging and its job

                                           13
is to show what the model does on these tasks when told only that unseen tests
exist. WARN is CTRL plus one sentence appended to the rules and nowhere else:
This task’s hidden tests are released in exactly K stages. K is the task’s
real stage count, so the warned model holds everything the control lacks about how
much is hidden. The sentence lives in the rules, which the model reads once at the
start of the episode, so it is told the total once and must track by itself how many stages
it has seen, and the feedback text was verified identical across the two arms in every
message except the first, which leaves the opening sentence as the only difference
between them. Both arms played the same 119 tasks in the same frozen order, 118
episodes came back under CTRL and 116 under WARN, and the pair cost $19.79.
Predictions: Four were registered. B1: the warned model claims at the decision point
on fewer tasks, which is the missing-information explanation put to the test, because
if ignorance of the count drives the claims then supplying the count must reduce
them. B2: wrong claims survive an explicit stage count, meaning at least one warned
claim is still wrong. B3: accuracy tracks how much a green board is worth, meaning
claims are wrong more often on the batch of tasks whose green boards are less often
the truth. B4: the warning changes the ending rather than the working, tested on the
window before the first decision point, which no claim can truncate, because if the
sentence changed how the model repairs code rather than when it stops, that early
window would show it.

7 Experiment 3: the incentive explanation
Bridge from Experiment 2: Experiment 2 ended with the model able to tell which
tasks are risky while still claiming on a fifth of the risky ones, so the next candidate
explanation is the criterion it applies. On that reading the model weighs the green
board correctly but sets its threshold by the stakes, claiming when being wrong looks
cheap, and a threshold set by the stakes must move when the stakes move. Experiment
3 therefore states a new price: it tells the model that stopping early is rewarded, and
watches whether claiming rises.
Changes from Experiment 2: Less than anywhere else in the programme. The corpus,
the frozen order and the model are unchanged, one new arm is played over the
first 72 ids of that order, and the comparison is made against the CTRL record from
Experiment 2 on the same ids. Two consequences follow: the comparison is again task
by task between two arms that differ in one sentence, and the two runs come from
different days, because the control was played in Experiment 2’s session, which is a
weakness this design accepts and Experiment 4’s churn floor later calibrates.
The arm: SIGMA is CTRL plus one sentence appended to the rules, stating that a DONE


                                             17
which turns out to be correct scores higher the fewer hidden stages the model has
seen, and that a DONE which turns out to be wrong scores the same as running out of
submissions. The sentence carries two clauses rather than one, because a reward with
no stated cost is an instruction to claim rather than a payoff, and the second clause
is true of this harness, since a wrong claim and an exhausted submission bound are
both terminal and both unsolved. 72 episodes came back, at $6.17.
The standing caveat: The payoff is stated and never delivered. Nothing in the harness
pays a bonus and no score is ever shown to the model, so an effect here would
be evidence that behaviour is sensitive to a described payoff structure rather than
evidence about a real one. This caveat travels with every result in this section.
The registered power: Power is the probability that a design detects a shift of a given
size, and the registration recorded this design’s power in advance: 0.80 at a shift of
0.155, 0.50 at 0.10 and 0.18 at 0.05. In words, a ten-point shift in the claim rate was a
coin flip for this design and a five-point shift was invisible, and the registration said
in advance that both would land in the disconfirmed cell.
Predictions: Three were registered. C1: the stated payoff makes the model claim on
more tasks, which is the incentive explanation put to the test, because a threshold set
by the stakes must move when the stakes move. C2: the extra claims come from tasks
where the model had been right to withhold, so accuracy among claims collapses,
which is what a lowered threshold costs. C5: the working phase has not drifted
between the two days on which the arms ran, tested, like Experiment 2’s B4, on the
window before the first decision point.
Results by arm: Under SIGMA the model played 72 tasks, said DONE at the decision
point on 42 of them, and 10 of those claims were wrong, shares close to the control’s
on the same tasks, so the totals move nowhere. The registered view is again the paired
one, task by task. Table 5 prints both, and the second panel of Figure 5 draws the tasks.
Reading the table: 71 tasks were played under both arms, and the four possible
answers sort as they did in Experiment 2: on 41 the model claimed at the decision

about the payoff. Six tasks changed answer, and five of the six changed against the
prediction, by claiming under the control and not under the payoff, while one changed

8 Experiment 4: the arithmetic at the decision point
Bridge from Experiment 3: The two failed interventions share a shape: each put a
fact in the rules at the start of the episode, and each therefore required the model
to retrieve that fact, hold it across the episode, and apply it many turns later at the
moment it mattered. Neither tested whether the model performs that retrieval, so one
explanation is still open, which is that the model has everything it needs and fails to
bring it together at the moment of the decision. Experiment 4 removes the carrying
requirement by putting the fact where the decision is made, already computed, and
watches whether claiming falls.
Changes from Experiment 3: The corpus, the frozen order, the model and the 72 ids
are all unchanged, and two new runs are played instead of one, both in the same
session. That repairs the weakness Experiment 3 accepted, because the control is
now played on the same day as its treatment, and it buys a second measurement for
free: the control contract has now been played twice on the same tasks with nothing
changed, so the pair of control runs measures how much this setup moves on its own,
a quantity this paper calls the churn floor. The treatment also moves channel, from
the rules the model reads once at the start to the feedback it reads at every turn, and
that relocation is the entire intervention.
The two arms: CTRL′ is the CTRL contract run again, changing nothing, so its job
is twofold: it is the same-day control for the new arm, and against Experiment 2’s
CTRL run it supplies the churn floor. COUNT is CTRL′ plus one line appended to the
feedback at every release, at a fixed registered position: Released so far: stage R
of K. Stages still withheld: N. R is the release index, K the task’s stage count,
and N the difference, so the line states, at the moment a fresh stage arrives, exactly
how much remains hidden. This is the first arm in the programme whose treatment
lives in the feedback channel rather than the rules. 72 episodes came back under
CTRL′ and 71 under COUNT, at $12.51.
The information content of the line: It carries no information the warned model
of Experiment 2 lacked, because K was in that arm’s rules and R is in the model’s
own transcript. What it adds is the subtraction, already performed, in the channel the
model is reading, at the moment the release creates the decision. If claiming falls here
after not falling in Experiment 2, the difference between the two arms’ fates cannot be
the information, which was the same, and must be something about where and when
it arrived.

made once every stage had been released were never wrong, 344 times out of 344,
and no claim was made after a submission that left a visible test failing, across 115
opportunities. The error is therefore concentrated at the one state where the visible
evidence is complete and the hidden evidence is not.

The proposed mechanism: The model reads a green board as evidence of completion
and applies a threshold to it. That threshold is too low for the tasks that hide something,
it is not moved by putting information about the hidden stages in the rules, and it is
not moved by attaching a payoff to stopping, yet the same information moves it when
it arrives already computed, in the channel the model is reading, at the moment of
the decision. The claim this paper makes is that the failure is one of integration at
the decision point, and the evidence for that claim is one experiment whose placebo
control has not been run.

10 Limitations
Every limitation below is taken from the programme’s own registrations and deviation
logs rather than assembled for this section, and each one names what it does and does
not put at risk.
   1. The placebo arm has not been run: Experiment 4 cannot separate the content
      of the counter line from the presence of an extra sentence of feedback. The
      registration recorded this before the run and the secondary analysis written to
      bear on it does not settle it. It is the largest open question in the paper, and the
      mechanism proposed in Section 9 depends on it.

   2. One model carries three of the four experiments: Experiments 2, 3 and 4 are all
      the same frontier model, so every elimination rests on one model. The capability
      result in Section 5 is three models, and it is the only claim here that is not
      single-model.


                                                   27
   3. One provider and one snapshot of it: Nothing here is replicated across providers,
      and a different frontier model could in principle behave differently at the decision
      point.

   4. The decisive experiment rests on 71 paired tasks: Effects in this programme
      live in counts of single digits, which is why every test is exact and why no
      confidence interval appears anywhere. A thirteen-against-one split is a strong
      result at this size and would still be a small sample at any other.

   5. Two of the comparisons cross a day boundary: Experiment 3’s arm ran the day
      after its control, and the churn floor calibrates this once, at 2 tasks of 71, but
      the floor says what a third identical run would probably do rather than what a
      different day would do, and it was measured only in the same session.

   6. The corpus is generated and its conventions come from a catalogue: Whether
      the same failure appears on organic under-specification in real repositories is
      untested, and the guarantee that makes this instrument work is exactly the
      guarantee a real repository cannot give.

   7. Experiment 1’s registration did not partition the outcome space: One prediction
      is recorded as neither confirmed nor disconfirmed because its two clauses left a
      gap and the run landed in it. Later registrations fixed this by requiring three
      clauses that partition.

   8. Episodes that never came back are dropped rather than counted: Four in
      Experiment 2 and one each elsewhere failed in transport, and each is excluded
      from the paired statistics rather than scored as a failure, because an absent
      episode is not an unsolved one.

   9. Operational deviations are logged rather than repaired: One publish gate
      was waived and recorded verbatim as a deviation, and a hash taken over a
      directory listing rather than over a named file set meant that two pooled figures
      in Experiment 2 print differently once later result files exist. The published
      values are quoted here, the population they are taken over is named, and no
      verdict moves either way.


11 Design implications and reproducibility
Design advice: The advice this programme licenses is narrower than the previous
paper’s, and it should be stated as such. If an agent must judge for itself when a
task is finished, put the state it needs in front of it at the moment it decides, already
computed. Putting the same fact in the system prompt did not work across 115 paired
tasks, attaching a payoff to stopping early did not work within a bound that rules out
a large increase, and printing one line of arithmetic into the feedback at the moment
of the decision moved 13 tasks against 1 and halved the wrong claims.
Two qualifications travel with that. The first is that the placebo arm has not run,

                                           28
so a designer following this advice is following a result whose mechanism is not
established. The second is that the intervention bought conservatism rather than
accuracy, and it was free here only because submitting again costs nothing on this
harness. A system that charges for a retry, whether in latency, tokens or a user’s
patience, will price that trade differently and should measure it before adopting the
line.
The quantity to instrument: The failure has a location and the location is cheap to
detect, because it is the state where every check the agent can run passes and the
agent knows more checks exist. A harness that logs nothing else can log that state
and count what its model does there, and that count is the quantity everything in this
paper turns on.
Scale and cost: The four experiments comprise 856 episodes over three models, the
eleven runs cost $55.21, and the whole programme including calibration probing that
produced no episode cost $61.25. An experiment that locates a reliability failure and
then tries three interventions against it fits inside a rounding error on a compute
budget, which is worth knowing before choosing to ship a harness on intuition instead.
Reproducibility: Every number in this paper is recomputed from committed episode
logs by one command, reading only frozen result files, task metadata and the checker,
with no model call and no key. The whole programme is also published as a flattened
dataset of five tables and 9,194 rows, extracted once and deterministically from the
seventeen committed result files, so a reader can ask a question with a GROUP BY
rather than by rerunning anything. Both corpora are pinned by content hash, each
experiment’s predictions are frozen at a commit that provably precedes its first live
call, and every deviation is recorded in an append-only log.
Provenance: The harness, scaffolding and analysis code were built with AI assistance
under execution-verified acceptance gates, with every phase advancing only on raw
command output audited by the author and all deviations logged. The research
questions, the registered predictions, the verification discipline and the interpretations
are the author’s.
